**Задача**:

Проанализируйте систему компании и C4-диаграмму в контексте планирования логирования. Опишите, какие логи нужно собирать и отметьте на схеме, из каких систем требуется сбор логов. Составьте список необходимых логов с уровнем INFO.
Например, изменение статуса заказа. Логируем время, идентификатор покупателя, номер заказа.
Напишите, будете ли вы использовать другие уровни логирования и при каких обстоятельствах

**Мотивация**

Логирование позволит отслеживать последовательность обработки данных в коде - т.е. оперативную диагностику и воспроизведение ошибок.

В первую очередь нужно добавить логирование запроса и ответа в CRM API и MES API (запрос получен API, сформирован ответ - его статус).

**Предлагаемое решение**
 
Глубину хранения логов предлагаю установить в 3 месяца (достаточно для диагностики большинства проблем).

Доступ к логам имеют сотрудники с активной учётной записью и ролями "Поддержка".

Технически логирование предлагаю реализовать при помощи ELK стека (Logstash + Elastic Search + Kibana).

Отдельные индексы в Elastic должны быть созданы для всех сред (dev, test, prod).

Алертинг в графана необходимо настроить для метрик:
1. Времени расчёта стоимости в MES
2. Метрики количества запросов в секунду полученных от внешних источников
