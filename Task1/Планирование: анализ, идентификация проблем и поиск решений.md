**Проблемы**:

1. Клиенты жалуются менеджерам по продажам, что они не получили заказ и над их изделием работают уже несколько месяцев, хотя обещали закончить за три недели.
2. Жалобы со стороны пользователей API. Представители компаний ежедневно сообщают, что не получили свои заказы.
3. Участились жалобы от операторов: когда они заходят на первую страницу MES, система долго прогружается. На первой странице отображается список заказов в работе по статусам — это дашборд с фильтром. Раньше страница показывала все заказы, но это тормозило загрузку. Команда сделала фильтр по статусам и пагинацию, но это не помогло. Операторам важно видеть самые новые заказы, потому что от этого зависит их вознаграждение, — кто взял заказ, тот и получит оплату.

**Проблемные места**:

1. Перегруженный операциями расчёта стоимости MES 
2. [3d file storage] - используется всеми API, отказ повлияет на всю систему.
3. Взаимодействие между Shop API и 3d file storage. Нужен кэш готовых 3d моделей для редактора, чтобы не нагружать хранилище лишними запросами.
4. Медленный расчёт стоимости в MES.
5. Общая база у [Shop API] и [CRM API] - потенциально может быть общей точкой отказа

**Первоочередные инициативы (тушим пожар)**:

1. Запросы от внешних продавцов (прямые в MES API) нужно пустить через очередь (аналогично внутренним запросам от собственного магазина)
2. Если у MES есть возможность масштабирования, то нужно поднять несколько инстансов (для ускорения расчёта стоимости).
3. Нужно снизить нагрузку на MES при помощи паттерна Backpressure. Запросы нужно поставить в очередь, дать возможность обработать самые старые (чтобы снизить негатив со стороны клиентов).

**Долгосрочные инициативы (идём к целевой архитектуре)**:

1. В MES выделить отдельный модуль для расчёта стоимости с возможностью его масштабирования (долгосрочная инициатива)
2. В MES для операторов показывать только заказы со статусом MANUFACTURING_APPROVED + в перспективе сделать распределение заказов по свободным операторам.
3. Хранилище 3d моделей разделить + создать кэш для хранения часто используемых моделей.

**Какой вы видите целевую архитектуру через полгода?**

1. Расчёт стоимости вынесен в отдельный масштабируемый модуль из MES
2. Все микросервисы можно автоматически масштабировать
3. Для всех БД настроена репликация

Для работ по выносу расчёта стоимости в отдельный модуль из MES нужно нанять + 1 или двух C# разработчиков (так как MES написана на C# и есть возможность реиспользовать код). Но предварительно нужно оценить сложность (силами техлида) + возможно переписать эту часть системы и на java (так как остальные бэкэнд модули на java).
