**Мотивация**

Кэшировать следует:

1. Запрос статуса заказа (интервал кэширования до 2 часов). Кэш статуса заказа позволит избежать лишней нагрузки на систему (например во время расчёта стоимости/создания нового заказа).
2. Запрос расчёта стоимости (интервал кэширования до 2 суток) - позволяет снизить нагрузку на MES (до завершения работ по выносу расчёта стоимости в отдельный модуль).

**Предлагаемое решение**

Предлагаю для кэширования данных о статусе заказа и запроса данных использовать серверное кэширование. В качестве кэша использовать Redis.

Для запроса статуса заказа использовать паттерн Cache-Aside (ключ кэша - идентификатор заказа, время жизни значения (TTL - 2 часа)). В случае обновления статуса необходимо обновлять значение в кэше (программная инвалидация). Паттерн Cache Aside лучше всего подходит так как оптимизируются операции чтения.

Необходимо предусмотреть возможность программной инвалидации при помощи запроса от администратора (очищается весь кэш по запросу).

Выбор стратегии инвалидации:

Статусы меняются по событиям внутри системы - 
при этом обновляется только одно значение по ключу - для такого сценария наиболее подходит программная инвалидация. Кроме того, чтобы кэш не заполнялся данными которые хранить нет необходимости нужно установить время жизни записи в кэше (TTL).
